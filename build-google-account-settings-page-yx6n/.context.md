# Goal
Deliver the first useful vertical slice: manage multiple Google Calendar accounts from one service-specific settings page.

# Priority
P0 — replaces hard-coded personal accounts and enables reusable multi-account Calendar support.

# Definition of Done
- `/google-calendar` opens a TUI settings page listing email and connection status only
- First-time setup imports a user-supplied Google Desktop OAuth client JSON; no shared client is bundled
- Add account requests fixed identity + Calendar-list read + Calendar-event read/write + free/busy read scopes
- Add rejects an already-connected identity without modifying it
- Remove confirms and deletes only the selected local account
- Remove then Add is the only re-authentication/replacement path in iteration one
- list-calendars discovers calendars across every connected account and preserves partial successes
- Other Calendar tools require explicit account email and calendar ID; there is no default
- RPC/non-TUI mode has a clear status/handoff fallback
- Tests cover missing/invalid OAuth client setup, empty accounts, add, cancel, duplicate, multiple accounts, unhealthy account, remove decline/confirm, and partial calendar discovery

# Product Decisions
- Calendar is independent from Gmail, Contacts, and Drive. Do not build a generalized Google account platform in this iteration.
- V1 uses a user-supplied Desktop OAuth client. Do not distribute a private, project-specific, or shared OAuth client.
- A project-operated, Calendar-only OAuth client may be offered later if adoption justifies its verification, privacy, quota, abuse, and support obligations.
- Private data lives outside the repository and `~/.pi`: macOS `~/Library/Application Support/pi-google-calendar/`, Linux `${XDG_DATA_HOME:-~/.local/share}/pi-google-calendar/`, Windows `%LOCALAPPDATA%/pi-google-calendar/`, overridable with `PI_GOOGLE_CALENDAR_DATA_DIR`.
- Google’s stable subject identifier is the account identity; token filenames use its hash. A newly verified email updates display metadata without creating a new identity.
- `list-calendars` returns one result per account, preserving successful calendars and reporting safe per-account errors with an explicit re-authentication indicator.
- Iteration one adds no runtime confirmation dialogs for Calendar mutations; that safety layer is deferred to iteration two.
