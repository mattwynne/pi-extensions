# Goal
Populate Calendar accounts only through the settings-page lifecycle so no personal identity appears in source or documentation.

# Priority
P0 — privacy and reuse release blocker.

# Definition of Done
- No account keys, emails, organizations, or private project identifiers are hard-coded
- The account registry is created and updated only by successful Add and confirmed Remove actions
- Each entry records stable Google identity, verified display email, credential reference, and health metadata
- Duplicate stable identities are rejected without mutation
- Migration instructions explain how current local accounts can be removed and re-added
- Tests cover empty, multiple, duplicate, stale, malformed, and removed records
