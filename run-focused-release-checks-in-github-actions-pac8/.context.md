# Goal
Run the same release-critical checks on every proposed change and public main update.

# Priority
P1 — release reliability.

# Definition of Done
- A minimal GitHub Actions workflow runs on pull requests and pushes to main
- It uses Node 24 and invokes only the root release-check command
- Dependency installation is reproducible from lockfiles
- Workflow permissions are read-only unless a specific step proves otherwise
- No credentials are required and no repository contents are uploaded to third-party actions beyond vetted pinned actions
- README shows the CI badge only after the public workflow succeeds

# Decision
Matt chose a focused CI gate rather than local-only or broad community-project automation.
