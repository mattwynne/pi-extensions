# Goal
Make the first public iteration honest and predictable about Calendar writes without adding runtime confirmation dialogs yet.

# Priority
P0 — documentation and defaults must match actual release behavior.

# Definition of Done
- Documentation states that explicit-intent checks are agent guidance, not an enforced confirmation control
- Create, update, move, and delete tools do not show runtime confirmation in iteration one
- `sendUpdates` defaults to `none` and notifications require an explicit non-default argument
- Tests cover mutation defaults and ensure attendee notifications are not sent accidentally
- Runtime confirmation is tracked separately for iteration two

# Product Decision
Iteration one ships without runtime mutation confirmation. Users rely on explicit tool intent and safe notification defaults. Native Pi confirmation dialogs are deferred to iteration two.
