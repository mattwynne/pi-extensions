# Goal
Create valid one-day all-day events when callers omit the end date.

# Priority
P1 — correctness.

# Definition of Done
- Omitted end defaults to the calendar day after start because Google uses an exclusive end date
- Explicit end remains treated as exclusive and is validated as later than start
- Invalid date strings and reversed/empty ranges fail before the API call
- Tests cover ordinary days, month/year boundaries, and leap days without timezone drift

# Known Knowns
- Current code defaults all-day end to the same date as start, producing an empty or invalid interval
