# Goal
After the Calendar settings-page MVP is working, evaluate migrating Calendar credentials to a supported Pi-native multi-account seam without changing user-facing behavior.

# Priority
P2 — explicitly deferred; does not block the first public Calendar release.

# Definition of Done
- Prototype the service-specific settings page against a supported credential API or document the missing Pi capability precisely
- Compare migration, locking, logout, account listing, and compatibility costs
- Decide whether to propose an upstream Pi API
- Preserve `/google-calendar` settings-page UX regardless of storage implementation
